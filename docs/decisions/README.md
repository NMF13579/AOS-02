# Architecture Decision Records

This directory is the canonical AOS-02 location for future, separately identified Architecture Decision Records (ADRs).

## What an ADR records

An ADR captures one bounded architecture decision: its question, context, considered alternatives, recommended option, trade-offs, consequences, dependencies, evidence, and open questions.

The required semantics are defined by the [Architecture Decision Record Contract](../governance/contracts/architecture-decision-record-contract.md).

## What an ADR does not do

An ADR is documentation of a decision. By itself it does **not** authorize implementation, runtime enforcement, code changes, migrations, commits, pushes, merges, releases, or any other live system change.

A proposed ADR is not accepted. An ADR becomes `HUMAN_ACCEPTED` only through a separate Human Decision Record bound to its exact revision.

## Boundary of this index

This index does not create, propose, or accept an ADR. It only establishes where a future ADR should be placed and which canonical contract governs it.
